# Rules for technical reports (requested by the user, apply to every report)

1. Simple yet rigorous language.
2. Every equation or theorem is defined and derived; assume no prior knowledge.
3. Every boundary condition and assumption is stated explicitly, with the reason it holds (the "why").
4. Deliver as an HTML document, with graphs, plots and images that help understanding.
5. Clear but essential and brief (not a 10-page report): direct to the point, yet every derivation introduced and explained.
6. The main goal is comprehension, not maximal rigour: when a topic is hard, use analogies or metaphors.
7. Interesting to read, not dry.
